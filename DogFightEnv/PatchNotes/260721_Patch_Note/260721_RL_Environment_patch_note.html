2. 업데이트 방법

  1. 기존 student/, 직접 만든 experiment YAML, 모델·checkpoint, 로그를 별도 보관합니다.
  2. 새 Release 압축본을 새 폴더에 완전히 압축 해제합니다. 구버전 폴더 위에 일부 파일만 덮어쓰지 않는 것을 권장합니다.
  3. tools/dogfight_dashboard와 tools/web_log_viewer 폴더가 모두 있는지 확인합니다.
  4. my_reward.py, my_observation.py 등 자신의 코드를 새 Release로 옮깁니다.
  5. 기존에 수정한 my_curriculum.py는 통째로 덮어쓰기보다 아래 병합 방법에 따라 scenario pool 부분을 추가합니다.
중요: 자신의 student/my_curriculum.py를 새 기본 파일로 덮어쓰면 기존 stage와 진급 조건을 잃을 수 있습니다. 먼저 백업하고 diff/병합하십시오.

3. Release tools 변경

3.1 Dashboard/Replay 경로 선택

  • 화면 상단에 Training logdir, Replay logdir, Apply, Reset이 추가되었습니다.
  • Apply 전에 경로가 현재 Release 루트 내부의 실제 디렉터리인지 확인합니다.
  • 선택 경로와 현재 tab이 URL query에 남아 같은 화면을 다시 열기 쉽습니다.
  • artifacts/dashboard, artifacts/logs, logs, engagement_replays 후보가 표시됩니다.
python tools\dashboard.py --port 7860

브라우저에서 http://127.0.0.1:7860을 열고 상단 경로를 선택한 뒤 Apply를 누릅니다.

3.2 특정 Replay 폴더를 CLI로 바로 열기

python tools\dashboard.py ^
  --default-tab replay ^
  --logdir artifacts\logs\<output-name>\<output-tag>\engagement_replays ^
  --port 7860

3.3 Release tools 독립 실행

launcher는 Release/tools 내부의 Dashboard와 Replay 패키지를 사용합니다. 필수 패키지가 누락되면 모호한 import 오류 대신 불완전한 배포본임을 설명하는 오류를 표시합니다. 기존 tools/training_dashboard/server.py와 tools/web_log_viewer.py도 호환용으로 유지됩니다.

화면에서 선택하는 경로는 현재 Release 환경 루트 내부만 허용됩니다. 다른 프로젝트나 상위 디렉터리를 지정하면 검증 단계에서 거부됩니다.

4. my_curriculum.py 초기 시나리오

student/my_curriculum.py의 MY_SCENARIO_POOL에 아군기와 적군기의 초기 상태를 여러 개 정의할 수 있습니다. 각 episode reset에서 환경 seed를 이용해 가중 선택합니다.

4.1 상태 벡터 계약

순서값단위·주의
0–2N, E, Dm. NED 좌표이므로 고도 7,000 m는 D=-7000
3–5roll, pitch, headingdegree
6speedm/s, 0 이상

4.2 실행 가능한 예제

MY_SCENARIO_POOL = {
    "mode": "scenario_pool",
    "scenarios": [
        {
            "name": "head_on_bt",
            "weight": 0.5,
            "ownship": [1000.0, 0.0, -7000.0, 0.0, 0.0, 0.0, 300.0],
            "target": [6000.0, 0.0, -7000.0, 0.0, 0.0, 180.0, 300.0],
            "target_mode": "behavior_tree",
        },
        {
            "name": "offset_loiter",
            "weight": 0.5,
            "ownship": [1000.0, -1000.0, -6800.0, 0.0, 0.0, 30.0, 280.0],
            "target": [5000.0, 1000.0, -7200.0, 0.0, 0.0, 180.0, 270.0],
            "target_mode": "loiter",
            "target_loiter": {"enabled": True, "bank": 35.0, "pitch": 0.0},
        },
    ],
    "ownship_randomization": {
        "enabled": True,
        "radius": 200.0,
        "r_heading": 15.0,
    },
    "target_randomization": {
        "enabled": True,
        "radius": 200.0,
        "r_heading": 15.0,
    },
    "shared_randomization": {
        "enabled": True,
        "n_m": 500.0,
        "e_m": 500.0,
        "d_m": 100.0,
    },
}

4.3 랜덤화 구분

설정의미대표 키
ownship_randomization아군기만 독립 랜덤화radius, r_heading, speed_mps
target_randomization적군기만 독립 랜덤화n_m, e_m, d_m, 자세 범위
shared_randomization같은 N/E/D·속도 offset을 양 기체에 적용하여 상대 기하 유지n_m, e_m, d_m, speed_mps

pool 공통값뿐 아니라 각 scenario 안에 같은 randomization dict를 넣어 해당 scenario만 override할 수 있습니다.

5. 자신의 curriculum에 병합하기

MY_SCENARIO_POOL을 정의한 뒤 사용할 CurriculumStage의 env_overrides에 연결합니다.

CurriculumStage(
    index=1,
    name="student_bt_dogfight",
    target_mode="behavior_tree",
    episode_step_limit=18000,
    max_iterations=20,
    checkpoint_interval=5,
    reward_overrides={},
    randomization={"enabled": False},
    env_overrides={"initial_scenario": MY_SCENARIO_POOL},
    advance_conditions={},
    advance_window=5,
)
중복 랜덤화 방지
scenario pool이 랜덤화를 담당하므로 해당 stage의 기존 randomization은 {"enabled": False}로 두는 것을 권장합니다.
BT provider 준비
pool에 behavior_tree 항목이 있으면 환경 생성 시 BT가 준비되도록 stage의 기본 target_mode도 behavior_tree로 둡니다.

6. 학습과 같은 stage로 로컬 검증

선택한 curriculum stage의 env_overrides를 로컬 교전에서도 재사용할 수 있습니다.

python run_local_dogfight.py ^
  --stages-module student.my_curriculum ^
  --stage-index 1 ^
  --ownship-backend rl ^
  --ownship-bundle-dir artifacts\models\team01\curriculum_v1 ^
  --target-backend bt ^
  --save-log
  • YAML의 초기 분포를 확인할 때는 --experiment-yaml experiments\<file>.yaml을 사용합니다.
  • 로컬 실행의 실제 적기 provider는 --target-backend가 결정합니다.
  • episode 지표에는 initial_scenario_index가 기록됩니다.
  • 저장 bundle metadata에는 scenario 이름·가중치와 설정 SHA-256 요약이 기록됩니다.

7. 호환성 및 주의사항

항목상태설명
기존 experiment YAML호환scenario_pool을 쓰지 않으면 기존 초기화 모드 유지
기존 curriculum호환기존 stage 정의를 그대로 사용할 수 있음
bundle / checkpoint호환관측·행동 계약을 변경하지 않음
Replay CSV호환기존 CSV pair를 새 tools에서 계속 재생 가능
기존 Dashboard CLI호환python tools/dashboard.py 및 --logdir 유지
Unreal 초기 spawn별도Unreal 서버가 spawn을 결정하므로 curriculum의 로컬 상태가 직접 적용되지 않음
재현성 확인: seed만 기록하지 말고 사용한 curriculum/YAML, bundle metadata의 initial scenario summary, episode의 scenario index를 함께 보관하십시오.
